Long description

AI agents can analyze markets and call financial tools, but capability is not authorization. A model holding a plausible instruction—or even credentials—does not prove that a specific action is permitted under current policy and evidence. The missing layer is an inspectable boundary between proposal and execution.

KACHING! is that boundary. It accepts an untrusted financial intent, observes account/market state, checks a partial Binance exchange contract, compiles code-configured policy and calculates a Decimal safe-action envelope. BLOCK and REVIEW authorize zero. Only ALLOW can issue a short-lived Ed25519 Authorization Lease bound to the exact origin, action, resource, amount, tool audience, policy hash and observation commitment.

The local Enforcement Lab proves the distinction. Present the exact signed action and the verifier returns VALID. Change the amount, resource, audience, signature or policy; use expired authority; or replay a consumed lease, and it returns a specific rejection reason. The deterministic demo reports 5/5 policy/evidence attacks contained and 7/7 authorization bypasses rejected. Receipt tampering is checked against a process-retained original digest.

KACHING! is deliberately non-executing. The browser and logical PEP place no order, transfer or withdrawal. Offline fixtures are clearly labeled, while an optional local --live mode performs read-only observations. The interface makes the trust transition visible: raw agent authority is NONE; REVIEW is not silent approval; and an edited draft immediately loses its displayed lease until it is recompiled.

This is a bounded hackathon prototype, not a production financial control. Fixture/live leases currently share a demo trust root, replay state is local and memory-only, and enforcement does not refresh balances or reserve funds. Those limits are explicit because proof-carrying authorization is useful only when its trust boundary is honest.

Claim limits

  • AuthZEN-inspired, not formally conformant.
  • The SHA-256 receipt digest is not the Ed25519 signature.
  • Fixture/live decisions share a demo trust root and lease mode is not encoded.
  • The logical PEP is in the same trusted local process.
  • Enforcement does not refresh state, reserve funds or aggregate spend.
  • Replay consumption is optional, bounded and memory-only.
  • Caller and subject labels are not authenticated identities.
  • VALID is local verification, not exchange execution or acceptance.
  • No Binance endorsement, security certification or profit claim.
